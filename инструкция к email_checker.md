# Email Checker — проверка валидности email-адресов

Python-скрипт для проверки email-адресов: валидация домена через MX-записи и SMTP handshake для проверки существования пользователя.

## Что делает скрипт

1. **Проверяет формат** email-адреса
2. **Проверяет MX-записи** домена через DNS over HTTPS (Google DNS)
3. **Выполняет SMTP handshake** — подключается к почтовому серверу и проверяет существование пользователя, не отправляя письмо

### Возможные статусы

| Статус | Значение |
|--------|----------|
| `домен валиден` | Домен существует, MX-записи найдены |
| `домен отсутствует` | Домен не зарегистрирован |
| `MX-записи отсутствуют или некорректны` | Домен есть, но не настроен для приёма почты |
| `некорректный формат email` | Адрес не соответствует формату `user@domain.tld` |
| `пользователь существует (код 250)` | SMTP-сервер подтвердил адрес |
| `пользователь не найден (код 550)` | SMTP-сервер отклонил адрес |
| `не удалось подключиться к SMTP` | Порт 25 заблокирован или сервер недоступен |

## Требования

- Python 3.10+
- Доступ в интернет (HTTPS и порт 25)
- Дополнительные библиотеки **не требуются** — скрипт использует только стандартную библиотеку Python

## Запуск

### Через аргументы командной строки

```bash
python3 email_checker.py user@gmail.com test@yahoo.com fake@nonexistent.com
```

### Интерактивный режим

```bash
python3 email_checker.py
```

Введите адреса по одному на строку. Пустая строка — запуск проверки.

## Пример вывода

```
==================================================
  Email : user@gmail.com
  MX    : домен валиден
  SMTP  : пользователь существует (код 250)

==================================================
  Email : fake@nonexistent.com
  MX    : домен отсутствует
```

## Ограничения

- Некоторые почтовые серверы (Gmail, Outlook) принимают любые адреса с кодом 250 — это защита от перебора, поэтому SMTP-проверка не гарантирует 100% точность
- Порт 25 может быть заблокирован вашим интернет-провайдером или хостингом — в этом случае SMTP-проверка покажет «не удалось подключиться»

## Возможные проблемы

### SSL-сертификаты на macOS

При установке Python с [python.org](https://python.org) на macOS он поставляется с **собственным хранилищем SSL-сертификатов**, отдельным от системного. По умолчанию это хранилище пустое, из-за чего Python не может выполнять HTTPS-запросы и выдаёт ошибку:

```
ssl.SSLCertVerificationError: [SSL: CERTIFICATE_VERIFY_FAILED]
certificate verify failed: unable to get local issuer certificate
```

Скрипт автоматически обрабатывает эту ситуацию и сделает запрос в обход проверки сертификатов, но для полноценной работы Python рекомендуется установить сертификаты.

#### Решение (способ 1 — рекомендуемый)

После установки Python в папке `/Applications/Python 3.X/` есть специальный скрипт. Запустите в Terminal:

```bash
/Applications/Python\ 3.13/Install\ Certificates.command
```

> Замените `3.13` на вашу версию Python. Узнать версию: `python3 --version`

Этот скрипт устанавливает пакет [certifi](https://pypi.org/project/certifi/) — набор корневых SSL-сертификатов от Mozilla (тех же, что используют Firefox и Chrome), и создаёт символическую ссылку, чтобы Python их видел.

#### Решение (способ 2 — ручная установка)

```bash
pip3 install certifi
```

Затем в Python выполните:

```python
import certifi
print(certifi.where())
```

Это покажет путь к файлу сертификатов. Если после установки `certifi` ошибка сохраняется, задайте переменную окружения:

```bash
export SSL_CERT_FILE=$(python3 -c "import certifi; print(certifi.where())")
```

Добавьте эту строку в `~/.zshrc` (macOS) или `~/.bashrc` (Linux), чтобы она применялась автоматически.

#### Это безопасно?

Да. Установка сертификатов:
- **не меняет** системные настройки macOS / Windows / Linux
- **не затрагивает** другие программы
- **не открывает** порты и не снижает безопасность
- наоборот, **без сертификатов** Python не может безопасно подключаться к сайтам по HTTPS

### Порт 25 заблокирован провайдером

Если SMTP-проверка выдаёт «не удалось подключиться к SMTP», скорее всего ваш интернет-провайдер или хостинг блокирует исходящие соединения на порт 25. Это распространённая практика для борьбы со спамом. В этом случае MX-проверка домена всё равно будет работать, но SMTP handshake — нет.

## Технологии

- Python 3 (стандартная библиотека)
- DNS over HTTPS (Google Public DNS)
- SMTP-протокол (smtplib)
